# Project structure: Toolchain and repository layout

> [Index](../README.md) · **Use for:** creating a new repo; deciding which folders and files exist. Placeholders are defined in the index.

## 1. Toolchain baseline

| Concern            | Default                                   | Notes |
|--------------------|-------------------------------------------|-------|
| Python             | ≥ 3.13, e.g. `>=3.13,<3.15`               | The same minor version in `pyproject`, the Docker image and CI |
| Dependency manager | **Poetry 2.x** (alternative: **uv**)      | One per repo, never mixed |
| Lock file          | `poetry.lock` / `uv.lock`, **committed**  | See [structure §3](02-dependencies-and-lockfiles.md) |
| Lint + format      | Ruff                                      | Replaces flake8, isort and black |
| Type check         | mypy (or pyright)                         | Strict on `src/`, relaxed on `tests/` |
| Tests              | pytest, pytest-asyncio, pytest-cov        | Add testcontainers for integration tests |
| Git hooks          | pre-commit                                | Runs the same checks as CI |
| Task runner        | Makefile                                  | The single entry point for developers |
| Containers         | Docker + Docker Compose v2                | Used for local infrastructure and the image build |
| Releases           | python-semantic-release + Conventional Commits | Automatic version bump and changelog |

Pin tool versions in three places: the dev dependencies, `.pre-commit-config.yaml`, and CI.
Keep all three in sync.

## 2. Repository skeleton

```
<service>/
├── src/
│   └── <package>/                 # src-layout: tests import the installed package, not the cwd
│       ├── __init__.py            # exposes __version__
│       ├── entrypoints/           # one file per process type: api.py, worker.py, cli.py
│       ├── api/                   # transport layer: app factory, routers, middleware, deps
│       ├── core/                  # config, container (composition root), errors, logging, security
│       ├── modules/               # one package per feature / bounded context
│       │   └── <feature>/
│       │       ├── api/           # routers for this feature
│       │       ├── schemas/       # request/response DTOs
│       │       ├── domain/        # entities, value objects, domain rules (pure)
│       │       ├── services/      # use cases / application logic
│       │       ├── ports.py       # interfaces this feature needs (repositories, clients)
│       │       └── adapters/      # implementations of those ports, one file per technology
│       ├── infrastructure/        # shared technical clients + lifecycle (one subfolder per technology)
│       │   ├── db/                # conditional: SQL engine / Mongo client
│       │   ├── cache/             # conditional: Redis client
│       │   ├── messaging/         # conditional: RabbitMQ / Kafka connection, publisher, consumer runner
│       │   ├── http/              # shared outbound HTTP client (timeouts, retries)
│       │   └── <other>/           # conditional: vector store, object storage, LLM provider SDKs…
│       └── shared/                # pure helpers with no I/O and no imports from modules/
├── tests/
│   ├── conftest.py
│   ├── fakes/                     # in-memory implementations of ports
│   ├── unit/                      # pure logic + services with fakes; no network, no Docker
│   ├── api/                       # HTTP/WS endpoints through the ASGI app, with fakes
│   └── integration/               # adapters against real infrastructure (testcontainers / compose)
├── migrations/                    # conditional: schema/index migrations (SQL: Alembic; document DB: migration tool or scripts)
├── scripts/                       # dev-only one-off scripts (seeding, probes); never imported by src
├── docker/
│   ├── app/Dockerfile             # one subfolder per image this repo builds
│   └── <infra>/                   # conditional: config files mounted into infra containers
├── docs/                          # conditional: ADRs (docs/adr/NNNN-title.md), diagrams, protocol specs
├── .github/ or .gitlab-ci.yml     # CI definition
├── pyproject.toml
├── poetry.lock                    # or uv.lock
├── poetry.toml                    # Poetry only: virtualenvs.in-project = true
├── Makefile
├── docker-compose.yml             # local dev stack: app + required infrastructure
├── .env.example                   # every setting, documented; secrets left blank
├── .gitignore
├── .dockerignore                  # allow-list
├── .pre-commit-config.yaml
├── .editorconfig
├── .python-version                # e.g. 3.13 (pyenv / uv read it)
├── README.md
├── API.md                         # conditional: client contract if not fully covered by OpenAPI
└── CHANGELOG.md                   # generated by semantic-release
```

Naming rules:

- Files and modules are `snake_case`. Routers are named `<feature>_router`. Test files are
  named `test_<unit>_<behaviour>.py`.
- Each package's `__init__.py` re-exports that package's public names through `__all__`.
  Nothing else in the codebase imports a package's private submodules.
- A file that grows past roughly 500 lines, or comes to hold a second concern, gets split.
